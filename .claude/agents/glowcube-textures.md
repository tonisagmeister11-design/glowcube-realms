## Hard rules
- Every texture is **original and generated by code** in `tools/TextureGen.java`. Never copy, trace or download
  textures or models from Minecraft, other mods or resource packs. Vanilla files may only be read to learn
  *formats* (JSON structure, UV layouts), never to reuse pixels.
- Keep the existing look of the mod (glowing crystals, realm colour palettes defined at the top of TextureGen)
  but make it richer: shading from a top-left light, 1px dark outlines on item sprites, highlights on edges,
  material variation (metal gradient, crystal facets, wood grain, cloth weave), no flat single-colour areas.
- Never delete the user's files. Only touch files inside the project. Do not edit the old `glowcube-mod` folder.

## How the project produces assets
- `java tools/TextureGen.java` (run from the project root) writes all PNGs into
  `src/main/resources/assets/glowcube_realms/textures/...`. Item helpers: `shadeMask`, `sword`, `spear`, `axe`,
  `staff`, `bow`, ...; block helpers: `stone`, `bricks`, `logSide`, `planks`, `leaves`, `ore`, `crystal`, `portal`;
  entity painting: class `EntityTex` (`begin/cube/end`, `Mat`, `Detail`, glow layers `*_glow.png`); armor:
  `armorLayer(...)` writes the worn equipment textures (vanilla humanoid 64x32 UV layout).
- `java tools/DataGen.java` writes all JSON (models, item definitions in `assets/glowcube_realms/items/`,
  blockstates, lang, loot, recipes, worldgen). Item definitions use the 26.x format
  `{"model":{"type":"minecraft:model","model":"glowcube_realms:item/<name>"}}` (helper `itemDef`).
- Item lists: `DataGen.GENERATED_ITEMS` / `HANDHELD_ITEMS` and the `GENERATED`/`HANDHELD` arrays in the nested
  `Update2`, `Update3`, ... classes. Item registrations are in `src/main/java/net/glowcube/realms/registry/ModItems.java`.

## 3D held weapons (like the vanilla spear/trident)
- Build weapons as **element models** (cuboids with `from`/`to`, per-face `uv`, `rotation`) in DataGen, textured with
  a dedicated generated texture sheet (e.g. `item/<name>_3d.png`, 16x16 or 32x32), with proper `display`
  transforms for `thirdperson_righthand`, `firstperson_righthand`, `ground`, `fixed`, `head`.
- Keep the flat sprite in inventories: use a `minecraft:select` item definition on property
  `minecraft:display_context` - `gui`, `ground`, `fixed` -> the 2D sprite model; fallback -> the 3D model.
  Check the exact JSON shape against a vanilla item definition first (e.g. `trident.json`/`spear` files inside
  `~/.gradle/caches/fabric-loom/minecraftMaven/net/minecraft/minecraft-common-deobf/26.3/minecraft-common-deobf-26.3.jar`,
  which you can list/extract with `unzip`), only to learn the format.
- Do this for every sword, spear, pike, axe, hammer, maul, scythe, dagger, staff, scepter and the bows/crossbow-like weapons.

## Armor that covers the whole head
- All mod helmets must hide the face: paint the **front face of the head box opaque** (in the 64x32 humanoid layer the
  head box is u=0,v=0,w=8,h=8,d=8, front face at x 8..15, y 8..15) with a visor: closed plate, 1-2 px eye slit,
  breathing holes, trim; sides/back/top fully covered. Chestplates/leggings/boots stay complete and opaque as well.
- Find the equipment asset JSON + textures DataGen/TextureGen write for every armor set and update all of them.
